# Yuka — 柴谷由佳

**人の可能性を、伝わる価値へ。**

小売・デジタル分析・インフルエンサーマーケティングの3領域での経験を伝える個人プロフィールサイトです。読者が「どんな視点を持つ人か」を理解できるよう、提供価値 → 経験 → 課題別の視点 → 価値観 → FAQ → 連絡先の順で構成しています。

## 開発を始める

Node.js 24（`.nvmrc`）とnpmを使用します。

```sh
npm ci
npm run dev
```

[ローカルサイト](http://127.0.0.1:3000/)を開いてください。停止は `Ctrl+C`。nvmを使用している場合は先に `nvm use` を実行します。
従来のルート直下のHTML/CSSはNext.jsへ移行しました。Pythonでソースフォルダを配信する手順は不要です。

| コマンド            | 用途                                         |
| ------------------- | -------------------------------------------- |
| `npm run dev`       | 開発サーバー。編集内容を自動反映             |
| `npm run lint`      | ESLintによる品質検査                         |
| `npm run typecheck` | Next.jsの型を生成し、strict TypeScriptで検査 |
| `npm run build`     | 本番用の静的ファイルを `out/` に生成         |
| `npm run preview`   | ビルド済みの `out/` をローカル配信           |
| `npm run check`     | lint・型検査・本番ビルドを順に実行           |
| `npm run test:e2e`  | 本番ビルドを対象にブラウザテスト             |

`npm run format` でコードと文書の書式を整え、`npm run format:check` で確認できます。

## 採用技術

Next.js 16 App Router / React 19 / TypeScript strict / Tailwind CSS 4。
具体的な版は `package.json` と `package-lock.json` に固定しています。アイコンはLucide、日本語はNoto Sans JP、欧文はDM SansとInstrument Serifです。

ページ本体はServer Componentで静的生成し、メニューとテーマ切り替えだけをClient Componentにしています。フォント・SVG・共有画像は同じサイトから配信します。外部フォントCDN、アクセス解析、認証、データベースはありません。

採用理由、出典・ライセンス、運用上の制約は [設計・運用記録](docs/architecture.md) を参照してください。

## 構成と編集場所

```text
src/
├── app/
│   ├── page.tsx                 # 情報設計とセクションの組み立て
│   ├── layout.tsx               # タイトル・説明文・OGP
│   ├── globals.css              # Tailwind・色・文字・共通スタイル
│   ├── icon.svg                 # ファビコン
│   ├── share-image.png/route.tsx # ビルド時生成の共有画像
│   └── not-found.tsx            # 404ページ
├── components/
│   ├── sections/                # 7つの独立したセクション
│   ├── site-header.tsx          # 追従ナビ・現在位置・読了進捗・モバイルメニュー
│   ├── site-footer.tsx          # 共通フッター
│   ├── section-link.tsx         # ページ内移動とフォーカス移動
│   ├── use-media-query.ts       # 画面幅と操作方向の同期
│   ├── perspective-tabs.tsx     # キーボード対応のテーマ切り替え
│   ├── orbit-art.tsx            # 独自SVGグラフィック
│   └── ui.tsx                   # コンテナ・見出しラベル・リンク
└── content/profile.ts          # 経歴・価値観・テーマ・FAQ・連絡先
```

経歴・FAQは `src/content/profile.ts`、導入文や個別の画面は `src/components/sections/` 内の対応するTSXを編集します。
`src/app/page.tsx` は7つのセクションを組み立てる入口です。単独のHTMLファイルやHTML文字列を埋め込む実装はありません。ブラウザへ配信するHTMLはNext.jsがReactから生成します。
配色はフォレストグリーン・アイボリー・シャンパンゴールドに統一しています。
色・フォント・共通の文字サイズは `globals.css` の `@theme` と共通クラスで管理し、配置はTailwindで指定します。

### プロフィールの掲載方針

文章の根拠は所有者から提供されたプロフィール情報です。第三者による経歴確認は行っていません。
未確認の順位・売上・職歴年月、実在しない顧客推薦は追加しません。内部の案件情報や社内戦略は、ソースやメタ情報にも含めません。
「課題別の視点」は思考の紹介であり、契約実績やサービス受付の表明ではありません。

### 連絡先

`profile.email` は現在 `null` です。「準備中」と表示し、送信ボタンやフォームは設けていません。
公開用メールアドレスが確定したら `profile.email` を設定し、同じファイルの問い合わせFAQも更新してください。
メールリンクの表示と実際の到達確認は別途必要です。個人用アドレスを推測で設定しないでください。

## 検証

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

テストは `out/` の本番ビルドを配信して実行します。ソース変更後は先に `npm run build` または `npm run check` を実行してください。
ポート3000の既存サーバーを再利用するため、別アプリや古い開発サーバーが動いていないことを確認します。
CIでは依存関係の導入、品質検査、Chromiumでのテストを実行します。デプロイは行いません。

自動テストの対象：

- 320 / 375 / 768 / 1024 / 1440px、および各幅のルート文字サイズ200%での横方向のはみ出し。
- テーマ切り替えのクリック・矢印・Home操作、モバイルメニューの選択・Escape操作。
- 本文へのスキップ、FAQ、動きを減らす設定。
- 追従ナビの現在位置、読了進捗、移動先の見出しがヘッダーに隠れないこと。
- axeによるWCAG A/AAの自動検出項目（通常、テーマ変更後、モバイルメニュー表示時）。
- メタ情報・共有画像・未設定の連絡先表示・JavaScript無効時の基本コンテンツ。

自動チェックはアクセシビリティ全体の適合証明ではありません。ルート文字サイズ200%はブラウザズームとは異なります。
実機・Safari・スクリーンリーダー・ブラウザズーム200%・本番環境は未検証です。

## 公開する

`output: "export"` を採用しているため、**配信するのは `out/` 全体**です。ソースのHTMLや `src/` をそのまま配信しません。公開先は未設定です。

1. `.env.example` を参考に、確定した公開URLを `SITE_URL` に設定する。
2. サブディレクトリ配信なら `NEXT_PUBLIC_BASE_PATH` を設定する（例：`/my-first-website`）。
3. `npm ci` → `npm run check` → `npm run test:e2e` を実行する。
4. `out/` を静的ホスティングへ配置し、公開URLで表示・CSS/JS/フォント・共有画像・主要操作・404を確認する。

`SITE_URL` 未設定時はcanonicalと共有画像の絶対URLを出力しません。未確定のドメインやlocalhostを公開メタ情報に埋め込まないためです。
サブディレクトリ配信の公開URLには、そのパスも含めます。basePathを変更した構成では、そのパスでの配信確認も別途必要です。
GitHub Pagesで使う場合は、Next.jsの `_next/` を配信できるよう `.nojekyll` またはPagesの静的アーティファクト配信を設定してください。

PRのマージは本番公開の完了を意味しません。公開先の設定と、公開後の実機確認を残タスクとして管理します。
